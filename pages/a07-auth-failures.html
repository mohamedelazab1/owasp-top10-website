OWASP-A07:2021

Identification & Authentication Failures

Confirmation of the user's identity, authentication, and session management is critical. Failures can lead to stolen accounts, session hijacking, password cracking, and account takeover.

Difficulty: Medium
Auth Sessions MFA Bypass

Real-World Incidents

Microsoft Storm-0558 (2023) — Outlook & Exchange

Chinese state-sponsored attackers forged authentication tokens by stealing a Microsoft signing key. The single key was trusted across consumer Microsoft accounts (Outlook.com, Live.com) and corporate ones (Azure AD). For over a month, attackers accessed the emails of ~25 organizations, including U.S. State and Commerce Departments. Root cause: a misconfigured consumer signing system that didn't enforce its audit logs and let an MSA key sign into enterprise environments.

Other Notable Incidents

  • LastPass (2022) — Encrypted password vaults were stolen after attackers compromised a senior DevOps engineer's home computer. Customer master passwords were then cracked using brute force on the stolen encrypted vaults.
  • Twitter Account Takeover (2020) — A 17-year-old socially engineered a Twitter employee into providing admin tools access. Result: takeover of Barack Obama, Joe Biden, Elon Musk, Apple, and other high-profile accounts to promote a Bitcoin scam.
  • GitHub OAuth Tokens (2022) — Heroku and Travis-CI had their GitHub OAuth tokens compromised via a stolen GitHub integration. Cascade to the entire customer base.
  • Okta Support System Breach (2022-2023) — Threat actors accessed Okta's support case management system, exposing sensitive files (HAR files, session tokens) that could be replayed to access customer environments.
  • Samsung Breach (2022) — Lapsus$ group used a compromised employee's session token to gain access to internal Samsung systems. The token was obtained from a previous breach and reused.
  • Yokogawa (2022) — A flaw in the password reset flow allowed attackers to take over accounts without knowing the old password.

How It Works

1. Weak Password Policies

Allowing "password" as a password. No minimum length. No breach-database check.

2. Credential Stuffing & Brute Force

No rate limiting, no CAPTCHA, no account lockout. Attackers throw 100M credential pairs at the login.

3. Session Token Mishandling

Sessions that don't expire. Tokens in URLs (leaked in Referer headers and logs). Tokens accepted from any IP after issuance.

4. Predictable Session IDs

Sequential or guessable session tokens. The attacker just enumerates.

5. MFA Bypass

The "remember this device" checkbox is permanent. The backup code is just another static secret. The push notification can be approved from an unattended phone.

6. Insecure Password Reset

Reset tokens that don't expire, can be reused, or are sent over plaintext email. "Security questions" with answers that are public (mother's maiden name, first pet).

7. Username Enumeration

Different error messages for "wrong email" vs "wrong password" let attackers enumerate which emails have accounts.

Vulnerable Code Examples

Example 1: No Rate Limiting on Login

Node.jsVulnerable
// ❌ No rate limiting, no lockout, no CAPTCHA
app.post('/login', async (req, res) => {
    const user = await db.users.findOne({ email: req.body.email });
    if (user && await bcrypt.compare(req.body.password, user.password)) {
        req.session.userId = user.id;
        res.send('ok');
    } else {
        res.status(401).send('Invalid email or password');
        // ❌ Same response either way → can't tell if email exists (good!)
        // ❌ But no rate limit → attacker tries 10k passwords/minute
    }
});

Example 2: Insecure Password Reset (No Expiry, No Single-Use)

Node.jsVulnerable
// ❌ Reset token never expires
app.post('/forgot-password', async (req, res) => {
    const token = Math.random().toString(36).substring(2);  // Predictable!
    await db.users.updateOne(
        { email: req.body.email },
        { $set: { resetToken: token } }
    );
    await email.send(req.body.email, `Reset: /reset?token=${token}`);
    res.send('Sent');
});

app.post('/reset-password', async (req, res) => {
    const user = await db.users.findOne({ resetToken: req.body.token });
    // ❌ No check that the token has expired
    // ❌ No check that it has been used before
    // ❌ Same token can reset the same account again from another browser
    if (user) {
        user.password = await bcrypt.hash(req.body.password, 12);
        // ❌ Forgot to clear resetToken → can be reused forever
        await user.save();
    }
});

Attack Walkthrough — Credential Stuffing

1
Acquire a credential list

Download a breach database — "Collection #1" (2.7B records), or buy a "combo list" on the dark web.

2
Set up a credential-stuffing tool

OpenBullet 2 (now-defunct, sadly still used in the wild) or Hydra. They run thousands of attempts per minute through residential proxies to avoid IP blocks.

3
Filter for successes

Look for HTTP 200 responses (login successful). Triage by account value (admin emails, emails at @target.com).

4
Pivot

Log in to the target's other services using the same password. Send phishing from the compromised email. Wire-transfer money from financial accounts.

CLIHydra example
# Brute force / credential stuffing login
hydra -L emails.txt -P passwords.txt target.com http-post-form \
  "/login:email=^USER^&password=^PASS^:F=Invalid password" -t 64

# -L: file of usernames
# -P: file of passwords (or combo list)
# -t 64: 64 parallel connections
# F=: pattern that means "this is a failure"
# Hydra will report any successful combination.

Secure Authentication

1. Strong Login Flow

Node.jsSecure
const rateLimit = require('express-rate-limit');

const loginLimiter = rateLimit({
    windowMs: 15 * 60 * 1000,  // 15 minutes
    max: 10,                     // 10 attempts per IP
    skipSuccessfulRequests: true,
});

app.post('/login', loginLimiter, async (req, res) => {
    const user = await db.users.findOne({ email: req.body.email });
    // ✅ Always run bcrypt even if user doesn't exist
    //    → prevents user enumeration via timing
    const dummy = '$2b$12$..invalidsaltinvalidsaltinvalidsa..';
    const hash = user ? user.password : dummy;
    const ok = await bcrypt.compare(req.body.password, hash);

    if (user && ok) {
        // ✅ Regenerate session ID on login (prevents session fixation)
        req.session.regenerate(() => {
            req.session.userId = user.id;
            res.send('ok');
        });
    } else {
        // ✅ Generic error message — same for "no user" and "wrong password"
        res.status(401).send('Invalid email or password');
    }
});

2. Secure Password Reset

Node.jsSecure
const crypto = require('crypto');

app.post('/forgot-password', async (req, res) => {
    // ✅ CSPRNG token
    const token = crypto.randomBytes(32).toString('hex');
    const expires = new Date(Date.now() + 15 * 60 * 1000);  // 15 minutes

    await db.users.updateOne(
        { email: req.body.email },
        { $set: { resetToken: token, resetExpires: expires } }
    );

    // ✅ Always return the same response — don't leak whether email exists
    res.send('If an account with that email exists, a reset link has been sent.');

    // Send asynchronously
    if (email) await email.send(req.body.email, `Reset: /reset?token=${token}`);
});

app.post('/reset-password', async (req, res) => {
    const user = await db.users.findOne({
        resetToken: req.body.token,
        resetExpires: { $gt: new Date() }   // ✅ Expired tokens rejected
    });
    if (!user) return res.status(400).send('Invalid or expired link');

    user.password = await bcrypt.hash(req.body.password, 12);
    user.resetToken = null;                  // ✅ Single-use
    user.resetExpires = null;
    await user.save();

    // ✅ Invalidate all other sessions for safety
    await db.sessions.deleteMany({ userId: user.id });
    res.send('Password reset. Please log in.');
});

3. Secure Session Cookies

Express (cookie-session)Secure
app.use(session({
    name: 'sid',
    secret: process.env.SESSION_SECRET,  // Strong secret, rotated regularly
    resave: false,
    saveUninitialized: false,
    cookie: {
        httpOnly: true,                  // ✅ Not readable from JS
        secure: true,                    // ✅ HTTPS only
        sameSite: 'lax',                 // ✅ CSRF protection
        maxAge: 1000 * 60 * 30          // ✅ 30-minute timeout
    }
}));

4. MFA Done Right

  • Use TOTP (RFC 6238) or WebAuthn / passkeys. SMS is the worst — vulnerable to SIM swapping.
  • "Remember this device" should be a short-lived signed cookie (e.g., 30 days), not a permanent one.
  • Always require MFA for sensitive actions: changing password, changing email, viewing API keys, large transactions.
  • Use number-matching for push notifications (Microsoft, Duo, Okta all do this now).

Prevention Checklist

✅ Authentication Hardening
  • Enforce a minimum password length (12+ chars) and check against known breach lists.
  • Rate limit login, password reset, and MFA endpoints. Lock out after N attempts.
  • Use generic error messages that don't leak which emails exist.
  • Always run password verification (even with dummy hashes) to prevent timing attacks.
  • Regenerate session IDs on login. Set idle timeouts (15-30 min) and absolute timeouts (1-7 days).
  • Use httpOnly, secure, sameSite=lax (or strict) cookies.
  • Require MFA for sensitive accounts and actions.
  • Issue cryptographically random, single-use, time-limited reset tokens.
  • Centralize identity (Auth0, Okta, Cognito, Keycloak) when feasible.
